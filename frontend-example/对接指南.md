# 前端 HTML 页面 × 自动更新数据库 —— 对接指南

> 适用场景：你用 AI 工具开发一个纯 HTML 前端页面，需要读取 GitHub 上由 gjj-policy-watch 每周自动更新的 `gjj_policy_database.json`。

---

## 一、方案对比与推荐

| 方案 | 原理 | 私有仓库可用 | 跨域/缓存问题 | 推荐度 |
|---|---|---|---|---|
| **A. JSON 随站点发布（推荐）** | CI 把最新 db.json 推送到 Pages 站点，HTML 同域 `fetch('./db.json')` | ✅ | 无 | ★★★★★ |
| B. 前端直接 fetch raw.githubusercontent.com | 运行时读仓库原始文件 | ❌（需 token，有泄露风险） | 有缓存 | ★★（仅公开仓库） |
| C. jsDelivr CDN 代理 GitHub | `cdn.jsdelivr.net/gh/user/repo@main/data/...json` | ❌ | 缓存 12h+ | ★★（仅公开仓库） |

**推荐方案 A**：数据库更新 → CI 自动同步 → 站点更新，全链路 git 可回溯，前端零配置。

---

## 二、方案 A 落地步骤（二选一）

### 路子 1：单仓库最简版（HTML 就放在数据仓库里）

适合：前端只有一个/几个 HTML 文件，不想维护第二个仓库。

1. 在 `gjj-policy-watch` 仓库新建 `docs/` 目录，放入：
   - `docs/index.html` —— 你的前端页面（可直接用附带的示例）
   - `docs/db.json` —— 数据库副本（首次手动复制一次即可）
2. 把附带的 `workflows/publish-db-same-repo.yml` 复制到仓库 `.github/workflows/` 下
   —— 它会在每周 PR 合并后（或数据库文件变更时）自动把最新的 `data/gjj_policy_database.json` 复制为 `docs/db.json` 并提交。
3. 仓库 Settings → Pages → Source 选 **"Deploy from a branch"** → 分支 `main`、目录 `/docs` → Save。
4. 站点地址：`https://<用户名>.github.io/gjj-policy-watch/`

数据流：weekly PR 合并 → publish 工作流检测 `data/gjj_policy_database.json` 变更 → 自动更新 `docs/db.json` → Pages 自动重新部署。全程无需人工干预。

### 路子 2：双仓库版（前端独立仓库）

适合：前端会发展成多页面项目，想独立维护。

1. 新建仓库 `gjj-portal`（可公开），放入 `index.html` 并开启 GitHub Pages（根目录或 /docs）。
2. 在 `gjj-portal` 仓库 Settings → Secrets 创建 `DATA_REPO_PAT`：
   - 到 GitHub → Settings → Developer settings → Personal access tokens → Fine-grained token
   - 权限：只选 `gjj-policy-watch` 仓库，Contents: **Read-only**
3. 把附带的 `workflows/sync-db-cross-repo.yml` 放到 `gjj-portal` 的 `.github/workflows/` 下，
   并修改文件顶部的 `DATA_REPO: "你的用户名/gjj-policy-watch"`。
4. 该工作流每周一 10:00（在数据仓库周报 PR 之后）自动拉取最新 db.json、提交并触发 Pages 部署；
   也支持在数据仓库的 weekly.yml 里加一步 `repository_dispatch` 实现"合并即触发"（文件内有注释说明）。

## 三、前端页面如何读数据（核心代码）

数据库结构（schema 稳定，不会变）：

```jsonc
{
  "database": "中国主要城市住房公积金政策数据库",
  "version": "1.1.0",
  "generated_at": "2026-08-20",
  "city_count": 134,
  "cities": [
    {
      "city": "深圳", "province": "广东", "last_updated": "2026-08-20",
      "official_site": "https://...",
      "deposit":    { "base_upper": 48471, "base_lower": 2520, "ratio": "5%-12%",
                      "period": "...", "note": "...", "sources": [{"title","url","date"}] },
      "withdrawal": { "conditions": ["..."], "rent_limit": "...", "note": "...", "sources": [...] },
      "loan":       { "max_single": "...", "max_family": "...", "rate_first": "...",
                      "rate_second": "...", "down_payment_first": "...", "down_payment_second": "...",
                      "conditions": "...", "note": "...", "sources": [...] }
    }
  ]
}
```

页面里只需要（示例 `index.html` 已完整实现，可直接用或交给 AI 工具参考）：

```js
const res = await fetch('./db.json?v=' + Date.now());  // ?v= 防缓存
const db = await res.json();
// db.cities 就是 134 城数组，字段为 null 表示"未找到官方公开来源"
```

**给 AI 开发工具的提示词建议**：
> "这是一个公积金政策查询页面。数据来自同目录的 db.json（fetch 时加 ?v=Date.now() 防缓存），结构为 { cities: [{ city, province, deposit:{base_upper,base_lower,ratio,period,note,sources:[{title,url,date}]}, withdrawal:{conditions[],rent_limit,note,sources}, loan:{max_single,max_family,rate_first,rate_second,down_payment_first,down_payment_second,conditions,note,sources} }] }。null 字段显示为'—'。sources 渲染为可点击的来源链接。"

## 四、注意事项

1. **缓存**：fetch 加 `?v=时间戳`（示例已内置），否则 Pages/CDN 缓存会导致看不到最新数据。
2. **Pages 部署延迟**：push 后 GitHub Pages 约 1-2 分钟生效。
3. **私有仓库 Pages**：免费账号的私有仓库 Pages 有功能限制（公开可见）；若数据敏感，改用路子 2 并把门户仓库也设为私有 + 升级方案，或部署到自己的服务器（直接复制 index.html + db.json 即可，无需任何后端）。
4. **变更通知**：想知道"这周哪些城市政策变了"，看数据仓库 weekly PR 的 diff，或读 `data/change_log.json`；前端如需"本周更新"板块，可让同步工作流一并复制 `change_log.json`。
